正式内容为五章十五主线、五个独立挑战，共六十项历史评价。所有关卡、完整结局及当前声音均已获用户试玩确认。布局、机关、光点、装饰、解法和基准以对应单关稿为唯一依据；实现者不得擅改谜题或 targets。

## 挑战

第一章通关解锁挑战一，其余各母章三关全收集后解锁。完成后仅在下一编号挑战已解锁时提供“下一关”，否则回选关，不跳过锁定项、不进入十五灯结局。

| [挑战4 递位](challenge-4.md) | 推动 | 18／22 | 1 | 同箱三阶段交接 |
| [挑战5 相托](challenge-5.md) | 遮挡 | 19／28 | 1 | 运箱返家、巡逻换岗 |

前三挑战无死局，后两关有后期阶段错误；全部首步／两步前缀可恢复不等于所有探索安全。提示与无限撤销是恢复入口，不修改规则禁止合法动作。

五挑战共用[评价与提示](../design.md#撤销步数评价与提示)、[通关流程](../design.md#通关与结局)和[音乐约定](../design.md#音乐)：复用母章谱面并统一90%速度，不新增首次教学或常驻解法说明。

全部提示须为合法动作且严格缩短获胜距离；反事实只过滤规则层已有动作，不改原关卡或规则。净空按[运动净空规范](../level-design.md#运动净空)覆盖顶板、岩层、机关与底盘，挑战四、五另含门、箱及巡逻。精确结果保留在单关基准，设备与采样限制见[验收记录](../performance.md#仍未覆盖)。

## 章节衔接与恢复边界

- 前六关由静态错觉到转动、乘坐、换乘、显露和双桥返程；第四至六关的实体纵深须满足运动净空规范。
- 第七关允许章首缓冲，第八／九关增加共享控制和调用后的状态恢复；第十关只降低推箱操作门槛，仍要求乘坐、运箱和返程。
- 第十一关须在箱留转角压住低廊时触发出口，再改压主线门；第十二关赴远庭取光时箱须留中站。两关存在后期死局，不能用其数量宣称更难。
- 第十二关把手8次，最优使用4次，余量允许额外完整往返；可绕后反推恢复过早箱位。经过call-far收光不等于停板开门；全部首步／两步前缀可解不保证额度耗尽后一次撤销就恢复。
- 第五章承接重量与运输规划。十三关选做须改变巡逻守板位置；十四／十五关运输不限次，前两步可恢复。终章提前停exchange会破坏最终交接，须撤销；联动与箱／巡逻职责交换不能省略。
- 第九、十二关有三灯庭院回应，正常2.2秒／减少动态0.2秒后显示结果；第十五关按数据演出十五灯和塔。音乐与界面共同行为集中在[游戏设计](../design.md)。

## 如何维护设计稿

每份稿保留教学点、投影草图、坐标与元素清单、标准解、干扰／恢复、难度目标和完整参考实现。`## 完整参考实现`（TS）与 `## 自动验证基准`（JSON）标题和代码围栏被校验器读取，不删除或改格式。前六关对应参考实现也作为正式设计依据保留。

先读[关卡制作规范](../level-design.md)及[运动净空](../level-design.md#运动净空)，按完整稿实现，不额外补路或借旧版本数据。修改任一谜题须先获得用户和指定设计者授权；正式设计与源码、targets不一致时先反馈，不删断言或放宽门槛。修订只影响对应关的旧评价，不能清空全部存档。

屏幕草图通常使用 `(a,b)=(x-y,z-y)`；`@`为起点，`G`为灯笼，`o`／`O`为必需／选做光点，数字为高度。具体以各稿图例为准，不能把投影坐标直接当世界坐标。

## 校验工具

```bash
node docs/levels/check-designs.mjs --runtime
node docs/levels/check-chapter5.mjs --runtime
node docs/levels/check-challenges.mjs --runtime
npm run typecheck && npm run format:check && npm test && npm run build
```

前三个命令分别核对第7～12关、第五章、五挑战的完整TS、源码／targets一致性、最短与全收集解、全部提示、关键反事实及181姿态净空；同时保护既有正式数据。去掉 `--runtime` 只检查设计，不能代替正式对象比对。前六关由正常测试与单关稿覆盖。

[chapter-scores.mjs](chapter-scores.mjs)和[chapter-5-score.mjs](chapter-5-score.mjs)为第三至五章独立谱面基准，校验器会与源码比对，不进入站点运行。精确指标在各稿JSON中，数值通过不代替用户难度体验或真机性能验证。
