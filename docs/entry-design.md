# 标题与选关页面设计交接（T6.12o2）

2026-10-21，用户要求把入口页面完善纳入本轮关卡开发。**T6.12t2 已实现标题页，T6.12t3 已实现选关页。** 本稿的尺寸、文案和状态仍是实现依据。T6.12u2 按用户要求移除正常标题的独立叠庭入口，样段仅供内部通过 `?sample=1` 回归；下文入口规范已同步。

## 设计意图与现状

视觉主张：沿用暖色渐变、浅色路面与青绿结构，让完整建筑和安静的排版共同构成入口。标题的文字与建筑各有空间；选关保留章节分组，以一次只有一座建筑的预览帮助辨认关卡。字体仍使用系统中文字体，无新图标库、字体、图片或音频。

内容顺序：标题先认识作品，再看到明确的继续目标；选关先确认进度与下一站，再选择重玩或继续。交互只保留按钮色差、焦点轮廓、预览切换的短淡入，遵守减少动态效果。画布不演示解法，不自行操作机关。

o2 设计时对旧页面的核对记录（当前 t2／t3 已实现）：

- 当前标题把品牌、评价和按钮叠在第一关建筑上，文字与路面争夺注意。
- “已点亮 15/18”实际是三项评价总数；六关均抵达也可能只有 15 项评价。新版分别称“主线已抵达”和“已获评价”。
- 当前选关已有章节与三项评价，但所有卡片构成相同，下一站和锁定原因不突出。新版保留一按即进入的操作，增加下一站、简短主题与桌面建筑预览。

## 本轮范围与开发顺序

按 `p → q → r → s → t → t1 → t2 → t3 → u` 逐项开发：p 为共用反馈，q～t1 实现新二至六关，**T6.12t2 标题页**、**T6.12t3 选关页**，最后 u 验收从入口到六关的完整流程。一项一个提交，不推送。

本轮不制作每卡缩略图、多画布墙、章节地图、章节解锁演出、分层提示、新音乐或全局通关演出。关卡特色由简短主题和桌面单一建筑预览表达。挑战列表为空就继续隐藏，不增加第七关或未来章节占位卡；独立叠庭仅保留内部 `?sample=1` 入口，不在正常页面提供按钮或链接。

不改解锁、评价、存档或相机规则。`firstPlayableIndex`、`isUnlocked` 仍是对应选择与解锁的依据。没有未完成棋盘的持久化，文案不能承诺恢复上一次动作位置。

## 标题页

### 内容与文案

| 顺序 | 元素 | 具体内容 |
| --- | --- | --- |
| 1 | 英文品牌辅助行 | Seemingly，可用现有系统字体大写排印，13 px |
| 2 | 主标题 | 积木错位 |
| 3 | 一句话 | 路看似相连，就能走过去。 |
| 4 | 进度，按下表决定是否显示 | 主线已抵达 `{mainDone}/{mainCount}` · 已获评价 `{earned}/{ratingMax}` |
| 5 | 主按钮与目标说明 | 开始旅程／继续旅程／重访旅程；说明见状态表 |
| 6 | 次按钮 | 选择关卡 |
| 固定工具 | 右上角静音按钮 | 静音／取消静音，读取既有 save.muted |

第一关初始场景作为右侧或中部建筑，读取 mainLevels[0]，保持固定等距方向和原布局。`Scene` 为 `interactive=false`、`tactile=false`；没有解法轮播、自动转动或可点击把手。建筑区域与文字区域通过布局分离，不靠加深渐变把文字压到建筑上。

### 主按钮状态与去向

| 主线状态 | 主按钮 | 目标说明 | 激活后的行为 |
| --- | --- | --- | --- |
| 没有主线抵达记录 | 开始旅程 | 前往 第 1 关 · `{实际关名}` | `play('main', firstPlayableIndex(save))`，从关卡开局进入 |
| 已抵达至少一关，尚未全部抵达 | 继续旅程 | 前往 第 `{index+1}` 关 · `{实际关名}` | index 来自 firstPlayableIndex；从开局进入首个尚未抵达关卡 |
| 当前主线全部抵达，无论评价是否齐全 | 重访旅程 | 当前开放的关卡已全部抵达 | goSelect；让玩家自行选关，不自动重开第六关 |

“继续”按**抵达记录**决定，不按 18 项评价是否齐全，也不按上一次点过的 sample／challenge 或当前内存中的关卡编号决定。例：只完成前三关，按钮去第四关；全部六关完成但评价 15/18，按钮为“重访旅程”。旧修订清除第二关后即使第五、第六关记录保留，也应继续第二关，不凭较大编号跳过缺口。

无主线记录且没有任何正式评价时隐藏进度行，保留其余顺序，不展示三个预先点亮的评价图标。部分完成与全部抵达时显示进度；若未来只有挑战记录，也可显示实际统计，但开始／继续仍按主线判断。主线抵达计数只遍历 mainLevels；评价计数遍历 `[...mainLevels, ...challengeLevels]` 的实际 ID，逐项加 done、allOrbs、parMet；ratingMax 为正式列表长度乘 3。忽略孤立旧 ID，sample 不参与；当前最大值为 18，不写死 6 或 18。

“选择关卡”始终 goSelect。正常标题不再提供独立体验；玩家按主线解锁正式第五关。`?sample=1` 仅作为内部回归入口，样段不计正式评价，返回标题后也不重新出现样段按钮。

静音按钮直接调用既有 toggleMute，aria-pressed 与 save.muted 一致，不新增声音设置。首次点击解锁 AudioContext 及原有标题主题由 App 处理，本任务不另建音频调度器。

### 桌面布局（宽度至少 960 px）

- 内容最大宽 1280 px，水平居中；页面内边距上下 72 px、左右 48 px，二列间隔 40 px。文字列 320～400 px，建筑列占剩余宽度，不加独立色块或分割线。
- 文字纵向居中；品牌辅助行 13 px／字距 0.24em，距主标题 14 px；主标题 48 px、行高 1.25、字重 500、字距 0.14em。
- 主标题后 20 px 为一句话，16 px／行高 1.75；后 24 px 为 13 px 进度行。主按钮 168 px 以上宽、48 px 高；目标说明 12 px、上间距 10 px。
- 主按钮组与次按钮间隔 12 px；次按钮同宽高，强调低于主按钮。次按钮下方不保留已移除样段入口的占位或留白。
- 建筑画布高度 `min(560px, 100svh - 144px)`，在右列内取景；较矮视口允许页面纵向滚动，不能把按钮压进建筑。右上工具距顶部 24 px、右侧 32 px，至少 44 px 高。

### 窄屏布局（宽度小于 960 px）

- 按品牌、主标题、一句话、建筑、进度、主按钮与目标说明、次按钮垂直排列，水平居中。文字不绝对定位到画布上。
- 左右内边距 24 px，顶部基础留白 40 px，底部 24 px；叠加对应 safe-area-inset。静音按钮距安全区上／右各 12 px，不覆盖居中的品牌文字。
- 主标题 32 px、行高 1.3；品牌辅助行 11 px，一句话 14 px。建筑区域高 `clamp(180px, 35svh, 260px)`，上下 8 px；继续使用第一关的 CameraRig 自动取景，不改相机方向。
- 主／次按钮宽 `min(320px, 100%)`、高 48 px，目标说明 12 px。375×667 普通字号应完整可见，320×568 或大字体允许正常纵向滚动。
- 使用可滚动的页面内容层，不能沿用全局 body overflow:hidden 再用绝对定位裁掉底部按钮；不改变关内画布的触摸设置。

## 选关页

### 总体结构

正常文档流中依次为：返回标题与静音工具、h1“选择关卡”、同标题页的进度行、实际存在的章节、评价说明。没有覆盖卡片的固定页头；整页可纵向滚动，touch-action:pan-y。每章标题用 h2，正文只保留一个 h1。

桌面正文为左侧章节卡片、右侧建筑预览。卡片仍是一按即进入该关：hover／键盘 focus 只改变预览，不要求先选择、再点击“进入”；禁用卡片无法激活。预览区域没有第二个“开始”按钮。

| 关卡 ID | 当前目标关名（显示仍读实际数据） | 固定主题短句 |
| --- | --- | --- |
| level-01 | 启程 | 第一束光 |
| level-02 | 转动 | 改变连接 |
| level-03 | 随行 | 随建筑移动 |
| level-04 | 换乘 | 庭院之间 |
| level-05 | 叠庭 | 层叠的庭院 |
| level-06 | 回环 | 两座桥的回程 |
| level-07 | 停靠 | 在停靠之间取舍 |
| level-08 | 联动 | 两处转轮，共用一座远桥 |
| level-09 | 牵引 | 召来远台，再恢复归路 |
| level-10 | 推动 | 把箱留下，人再回来 |
| level-11 | 越界 | 转过桥，再换推向 |
| level-12 | 重量 | 把重量留下，把自己送回 |

主题短句按 ID 存在 app 的展示数据中，不作为解法提示，不写入 rules、targets 或关卡 build；不要出现“先下台”“转两次”等答案。未来 ID 未定主题时可省略该行，不能随意给关卡编新机制或故事。名称、章号、卡片数与顺序一律读取实际关卡列表。

章标题保留“第一章 · 看似”“第二章 · 转动”，右侧显示 `{本章done}/{本章关数} 关已抵达`。空章整段隐藏。每章内部排列自己的关卡，手机第三张卡单独占下一行，不用下一章的卡来填空位。

### 卡片与状态优先级

每卡从上到下为两位显示序号、关名、主题短句、三项具名 Ratings；评价数量并入编号行，最少步数并入对应评价，状态只显示下一站／可探索／锁定原因。显示序号可补零为 01～12，实际索引仍为主线中的 index；补零不改 ID。Ratings 的语义与通关规则保持：抵达／集齐全部光点／最少步数。

| 条件，按此顺序判断 | 表现 | 激活／预览 |
| --- | --- | --- |
| isUnlocked 为 false | 淡底虚线边框，状态“先通过第 `{前一关显示序号}` 关”；若本关保留了旧有效抵达记录，状态前加“已抵达 · ”，评价照常保留 | 原生 disabled；不响应 hover、键盘或触摸，不切换预览 |
| 已解锁且 record.done | 不重复状态文字，抵达评价与数量体现进度 | 可重玩，hover／focus 可预览 |
| 已解锁且未抵达，等于 firstPlayableIndex，且非全主线抵达 | 状态“下一站”，青绿实线边框与浅底 | 可进入与预览 |
| 其他已解锁但未抵达 | 状态“可探索” | 可进入与预览 |

“下一站”由存档导出，不随 hover 改变；预览哪个关卡由本页临时状态决定，不能把这两件事混在一起。正常进度时只有一张下一站；全部抵达时没有下一站标签。不要把已有全部评价作为额外解锁条件。

逐关修订后可能存在记录缺口。必须继续调用 isUnlocked，不凭 done、最大编号或“前面看着都完成了”重写规则；保留记录但暂未解锁的卡仍禁用，显示已有评价及实际锁定原因，不清除后续记录，也不为使页面好看而解锁它。

挑战列表当前为空，整段隐藏。未来存在挑战关时沿用现有列表与 isUnlocked 条件，锁定原因仍按“通关第一章／集齐第某章选做光点”；本稿不设计挑战预览主题或改变解锁。sample 不出现在主线／挑战卡片中，也不在正常页面导流；内部通过 `?sample=1` 进入。

### 建筑预览

- 宽度至少 960 px 时显示一个预览画布，初始 index 为 firstPlayableIndex；全部主线抵达时该函数返回最后一关。检查其已解锁再显示，不可用时回退首个已解锁主线关卡。
- 卡片 hover 或键盘 focus 时预览该已解锁关的**初始状态**，移出后保持最后一次有效预览；点击直接 play。重新进入选关页时回到初始选择，不保存 hover 或增加“上次选中关卡”的存档字段。
- 预览下显示“第 N 关 · 实际关名”与上述主题。画布 aria-hidden，旁边文字提供内容；不能让隐藏画布中的把手参与键盘或指针交互。
- 复用现有 Scene、LevelSim 与 CameraRig，Scene `interactive=false`、`tactile=false`。只创建初始模拟器，不执行标准解法，不调用 prepareHints、solver、completeLevel 或 writeSave。相机方向不变；容器独立取景，不修改全局 CameraRig 来适配入口。
- 整个选关页最多一个 Canvas／WebGL 上下文，不给六张卡各建一个画布；切换时复用 Canvas，按 level.id 重建或重置内部 Scene／初始 sim，清理旧引用。只用已有共享几何体和材质。
- 宽度小于 960 px 不挂载预览画布，保留主题文字与状态；不能仅用 display:none 隐藏仍在更新的 Canvas。标题页自己的单画布保留。断点切换不能留下重复上下文。
- 预览选择是本地 React 状态，不修改 store.current，不触发 App 的章节音乐同步；鼠标在不同章节间移动不换音乐、不发机关音效。页面切换仍沿用既有标题／选关音乐策略。

## 颜色、焦点与动态效果

沿用 App 的暖色背景、现有 --ink、cream、plumDeep 和 teal。以下只用于 DOM CSS，不修改 palette.ts 或渲染材质：

- 正文及主按钮使用现有 --ink `#4a3a52`；主按钮文字 `#fff7ea`。次按钮用半透明现有 cream 底与1 px淡描边。
- 12～13 px 信息文字使用 plumDeep `#5b4569`，不要因“次要”再把整个容器降低透明度。
- 卡片普通底 `rgba(255,249,240,0.34)`、下一站底0.65、锁定底0.15；普通边为 `rgba(74,58,82,0.18)`，下一站边为 teal `#5f9894`，锁定边为虚线。锁定文字可读，不能复用全容器 opacity:0.4。
- 本页 Ratings 已获得图标用 plumDeep 描边、淡金背景 `rgba(255,217,138,0.6)`；未获得用现有 plum 描边，不加金底。复用原 SVG 路径与 aria-label；CSS 限定入口页作用域，不改变关内评价。
- 所有按钮最小点击高度44 px；键盘 focus-visible 用3 px深青绿 `#355e5b` 外轮廓、外偏移3 px；“下一站”还有文字，不能只靠颜色。locked 使用原生 disabled，未锁卡可 Tab、Enter／Space 激活。
- 卡片可访问名称应包含真实序号、关名、状态和三项评价；沿用 Ratings 的可访问描述，不用只有关名的 aria-label 覆盖这些信息。工具用原生 button，画布设 aria-hidden，不添加自动抢焦点。
- 主按钮、次按钮与卡片只做约140 ms的背景／描边回应；预览或内容组淡入最长240 ms，不移动布局、不让建筑旋转。减少动态效果时立即切换并关闭 CSS 过渡／入场效果，Scene 继续接收既有 reducedMotion。
- CSS 使用 `.entry-title`、`.entry-select` 等入口作用域，不能改通用 `.title h1`、`.hud-button`、`.ratings` 后连带改变游戏页。正式组件继续使用 App 已有背景容器，不重复嵌套一层 App 渐变。

## 评价含义与重玩目标（T6.12v3，按用户反馈整理）

选关卡分三层：顶部同一行显示编号与评价数量N/3；中部为关名、主题；下部以细分隔线组织三项具名评价，图标、文字、勾／短横固定对齐。最少步数行直接写“最少 N 步”，不另占一行重复目标或“不用提示”。已完成卡不重复显示“已抵达”；下一站、可探索及锁定原因仍保留。读屏保留完整评价状态与数量，卡片一按进入、原生禁用及桌面单预览不变。

完成卡只展示本次结果：关名、评价数量、三项图标、本次步数／最少步数及下一关／再试一次。使用提示时只在步数行附“已用提示”。按用户要求移除历史评价行、补评规则和其他重复说明，累计成绩由选关呈现；完成组件不再读取或接收历史记录。保存与判定不改。

保留暖色、系统字体与圆角；统一卡片内边距与行距，选关桌面三列、手机两列，内容自然增高。完成卡改为更实的暖白底，避免建筑透过文字干扰阅读；下一步按钮深色，重试保留浅色，均44px以上。沿用既有获得、悬停、焦点与低动态行为，不增加动效、资源或依赖。
