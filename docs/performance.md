# 性能检查（T5.1）

检查日期：2026-10-16。代码基线：`196f522`（M4 完成）。本次不改变画面、玩法、关卡或依赖。

## 范围与方法

- 使用 Playwright 1.62.1 与其本地 Chromium 运行时；电脑视口 1280×900、`?quality=high`，手机模拟视口 375×667、`?quality=low`；两者测试像素比均为 1。保留正常动态效果、云和光点。
- 通过真实界面选关、点击路面与把手，按九关自带解法游玩，包含压板自动触发与终章全部灯笼点亮。
- 读取 Three.js `WebGLRenderer.info.render.calls`。在 `Scene.onAfterRender` 收集整帧峰值，包含高画质的阴影 pass；开局预热 0.6 秒后采集 60 个动画帧。
- 动作等待以实际模拟器的只读状态为准，确认已空闲且角色、机关到位；点击后先截图刷新画面，避免把后台动画暂停当作逻辑错误。
- GPU 标识为 `ANGLE / Vulkan / SwiftShader Device (LLVM 10.0.0)`，属于软件渲染。下方帧时间是此测试环境的观测值，**不能据此声称集成显卡笔记本或中端手机已达到 60 FPS**；目标设备的实机帧率仍需补测。

## 首次加载

`npm run build` 生成静态站点。以下为 Node.js 24 `zlib.gzipSync` 默认参数计算的资源大小，不含 HTTP 头；部署服务的压缩参数可能略有差别。

| 首屏请求资源 | 原始字节 | gzip 字节 |
| --- | ---: | ---: |
| HTML | 737 | 490 |
| JavaScript | 1,183,120 | 323,344 |
| CSS | 5,833 | 1,786 |
| 图标 | 250 | 170 |
| **合计** | **1,189,940** | **325,790** |

首次压缩资源约 326 KB，为 1 MB 预算的 32.6%。Vite 自身报告 JavaScript gzip 326.25 KB，也在预算内。构建器的“单个 chunk 超过 500 KB”警告按未压缩大小触发，与项目的压缩传输预算不同；本次保留该提示，无需为消除提示而拆包。

复核方式：

```bash
npm run build
node --input-type=module -e 'import {readFileSync,readdirSync} from "node:fs"; import {gzipSync} from "node:zlib"; const paths=["dist/index.html","dist/favicon.svg",...readdirSync("dist/assets").map(n=>"dist/assets/"+n)]; console.log(paths.map(p=>[p,gzipSync(readFileSync(p)).length]));'
```

后续分享图只由社交抓取器读取，README 图片位于 `docs/assets/`，均不由游戏首屏请求。修改页面元信息后 HTML 体积会小幅变化，以上数字对应本节标明的 M4 基线。
