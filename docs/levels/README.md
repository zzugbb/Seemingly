## 怎么读屏幕草图

草图由求解器工具按开局状态打印，只画可行走的路面：

- 每一行是屏幕上的一条水平线，越往下离玩家越近；往右下走是 `+x`，往左下走是 `+z`。
- 数字：静态路面的高度 `y`。
- 字母：机关积木上的路面，`a` 表示高度 0，`b` 表示 1，`c` 表示 2，`d` 表示 3，依此类推。
- `@` 起点，`G` 灯笼（终点），`o` 必需光点，`O` 选做光点，`.` 开局时走不到。
- 草图上上下左右紧挨着的两格就是相连的，不管它们的高度差多少。

## 怎么用参考实现

- 每份设计稿都附有「参考实现」，这段代码已经用求解器和关卡校验验证过，全部通过。
- 实现者把它复制到 `src/game/levels/level-XX.ts`，坐标、机关、光点、解法都不要改。
- 可以补充的只有装饰：树、花、窗洞（规则见[构图](../level-design.md#构图)），以及积木颜色的微调（用途规则见[美术方向](../art-direction.md#配色)）。补完后重新跑测试，确认仍然通过。
- 「难度目标」一节的代码写进 `src/game/levels/targets.ts`。因为首版九关里有同名的 `level-01`～`level-06`，这些目标要在 T6.11 删除首版关卡的同一个提交里写入，否则测试会失败。
