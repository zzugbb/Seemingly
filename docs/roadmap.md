# 路线图

按编号顺序执行，一次只做一个任务。完成后把 `[ ]` 改成 `[x]`，与代码放在同一个提交里。

每个任务除了下面列出的验收标准，还必须通过：

```bash
npm run typecheck && npm run format:check && npm test && npm run build
```

## M1 核心系统

目标：把小样改造成目标架构，画面和玩法不变。

- [x] **T1.1 关卡数据格式**
  - 按 [architecture.md](architecture.md#关卡数据) 重写 `levels/types.ts`，新增 `levels/builders.ts`（`defineLevel` 及 `island`、`path`、`solid`、`column`、`rotator`、`mover`、`plate`、`start`、`goal`、`tree`、`flower`、`window`）。
  - 用新格式重写 `levels/prototype.ts`，转盘放进 `mechanisms` 列表；`World.tsx` 改为读取新格式。
  - 验收：画面与改造前的截图一致；`prototype.ts` 中不再出现十六进制色值。
- [x] **T1.2 机关计算**
  - 新增 `core/mechanisms.ts`：根据机关定义和当前档位或停靠位，算出每块机关积木的世界坐标；平移台的往返规则；压板的触发判断。
  - 验收：`core/mechanisms.test.ts` 覆盖转盘 4 个档位、平移台往返、`once` 压板。
- [x] **T1.3 可见性检测**
  - 新增 `core/visibility.ts`，实现顶面 5 点采样与射线检测。
  - 验收：测试覆盖「被前方柱子挡住」「错觉连接合格」「错觉连接违反遮挡规则」三种情况。
- [x] **T1.4 模拟器**
  - 新增 `core/sim.ts`，按 [architecture.md](architecture.md#模拟器) 实现 `LevelSim`。
  - 验收：`core/sim.test.ts` 覆盖行走、走不通、机关运动中拒绝指令、站在机关上拒绝操作、压板触发、通关后拒绝指令。
- [x] **T1.5 关卡校验与解法验证**
  - 新增 `core/validate.ts`、`core/solve.ts`、`levels/index.ts`、`levels/levels.test.ts`，实现 [level-design.md](level-design.md#校验) 的 7 项检查。
  - 小样的终点连接违反遮挡规则，在本任务中调整终点位置使其合格（例如把终点基座放到高度不低于桥臂的位置），并为小样写好解法。
  - 验收：小样通过全部校验；故意改坏一处坐标，测试能报出具体是哪一项、哪一格。
- [x] **T1.6 渲染由模拟器驱动**
  - 按目标目录拆分 `World.tsx`：`Scene`、`CameraRig`、`Lights`、`Blocks`、`Mechanisms`，每帧调用 `sim.update`，删除 `World.tsx`。
  - 验收：小样的玩法与画面不变；`render/` 中不再有寻路或机关规则的代码。
- [x] **T1.7 页面与存档**
  - 引入 zustand；新增 `app/store.ts`、`app/save.ts`、`app/screens/`、`app/hud/`，按[设计稿](design.md#界面流程)实现标题页、选关页、游戏页、结尾页的骨架。关卡列表暂时只有小样。
  - 验收：标题 → 选关 → 游戏 → 通关 → 下一关或结尾，流程走通；刷新页面后通关记录还在；`R`、`Esc` 快捷键生效。
- [x] **T1.8 线上验证**
  - 推送 M1 的全部改动后，确认 GitHub Actions 通过，`https://zzugbb.github.io/Seemingly/` 能打开新的标题页并游玩小样。
  - 验收：线上页面截图正常，浏览器控制台没有 404 资源。

## 已知问题（来自小样）

- 终点连接违反遮挡规则，桥臂侧面挡住了终点顶面一角（T1.5 修复）。
- 小人太小，颜色和路面接近，看不清（T2.1 修复）。
- 转轮点击区域偏小，手机上尚未验证（T2.4 检查）。
- 关卡只支持一个转盘（T1.1 修复）。
- `World.tsx` 混合了状态、交互和渲染（T1.6 修复）。
- 构建时提示单个脚本超过 500 KB；T5.1 已评估：这是未压缩体积提示，首屏 gzip 约 326 KB，符合 1 MB 传输预算，保留提示。
