# 关卡制作规范

> 制作或修改任何关卡前必读。关卡必须通过本文「校验」一节的全部检查。

## 坐标系

- 积木坐标为整数格 `(x, y, z)`，`y` 向上。
- 相机从 `(+1, +1, +1)` 方向看向场景。屏幕上：
  - `+x` 指向右下；
  - `+z` 指向左下；
  - `+y` 指向正上方。
- 每块积木只有三个面可见：顶面（`+y`）、右前面（`+x`，较暗）、左前面（`+z`，较亮）。
- 离相机越近，`x + y + z` 越大。

## 屏幕坐标

积木 `(x, y, z)` 的屏幕坐标为 `(a, b) = (x - y, z - y)`。

- 屏幕坐标相同的积木在画面上完全重合。
- 反过来，给定屏幕坐标 `(a, b)` 和高度 `y`，积木位置是 `(a + y, y, b + y)`。

**推荐的制作思路：先在屏幕坐标上画路线，再给每块路面选高度。** 屏幕上相邻、高度相同的路面是真实相邻；高度不同的就是错觉连接。

## 遮挡规则

两块屏幕相邻的路面 A、B，B 在 A 的屏幕下方（即 B 的 `a` 或 `b` 比 A 大 1）时：

> **B 的高度必须大于或等于 A 的高度。**

等价说法：屏幕上靠下的那块，必须离相机更近或一样近。违反时，A 的侧面会挡住 B 顶面的一角，错觉就穿帮了。

反过来，B 在 A 的屏幕上方时，B 的高度必须小于或等于 A 的高度。

示例：

| A | B | 结论 |
| --- | --- | --- |
| `(2, 0, 0)`，屏幕 `(2, 0)`，高度 0 | `(7, 4, 4)`，屏幕 `(3, 0)`，高度 4 | B 在下方且更高，合格 |
| `(11, 4, 4)`，屏幕 `(7, 0)`，高度 4 | `(9, 1, 1)`，屏幕 `(8, 0)`，高度 1 | B 在下方但更低，**不合格**（小样中的终点连接就是这种情况，正式关卡要改掉） |

除错觉连接本身外，路面还可能被前方的柱子、塔身挡住。这部分由下面的「可见性检查」自动发现。

## 关卡文件

- 每关一个文件：`src/game/levels/level-00.ts` 到 `level-08.ts`，序章是 `level-00`。
- 在 `src/game/levels/index.ts` 中按顺序导出关卡列表。
- 用 `src/game/levels/builders.ts` 中的辅助函数搭积木，不要手写大段坐标数组。
- 数据结构见 [architecture.md](architecture.md#关卡数据)。

示例骨架（坐标仅作示意）：

```ts
import { defineLevel } from './builders'

export default defineLevel({
  id: 'level-02',
  title: '转动',
  build: (b) => {
    b.island({ x: [-1, 2], z: [-1, 3], y: -1 })
    b.path([0, 0, 2], 'terracotta')
    b.path([0, 0, 1], 'terracotta')
    b.column({ x: 5, z: 3, from: 0, to: 2 }, 'rose')
    b.path([5, 3, 3], 'rose')
    b.rotator({
      id: 'bridge',
      pivot: [8, 3, 3],
      blocks: [{ offset: [0, 0, -1] }, { offset: [0, 0, 1] }],
      handle: { block: [8, 1, 3], face: 'z' },
    })
    b.start([0, 0, 2])
    b.goal([10, 3, 3])
    b.tree([-1, -1, 0])
  },
  solution: [
    { type: 'operate', mechanism: 'bridge' },
    { type: 'walk', to: [10, 3, 3] },
  ],
})
```

## 制作步骤

1. **定教学点**：对照[设计稿](design.md#关卡)，写下这一关的「原来如此」是什么，只引入一种新东西。
2. **画屏幕路线**：在纸面或注释里列出路线经过的屏幕坐标序列，以及终点位置。
3. **选高度**：给每段路选高度 `y`，换算成积木坐标，并检查每处错觉连接是否满足遮挡规则。
4. **补结构**：在高处的路面下方加柱子，一直连到岛屿；加岛屿和底部岩层。
5. **放机关**：确定每个机关在每个档位或停靠位下的积木位置，确保任何状态下都不和其他积木重叠。把手装在结构积木的可见侧面（`x` 或 `z` 面）。
6. **写解法**：按操作顺序写出解法步骤。
7. **跑校验**：`npm test`，全部通过。
8. **看画面**：`npm run dev` 打开该关，截图检查构图、错觉是否成立、装饰有没有挡住路。
9. **试玩**：亲手按解法走一遍，再试几条错误路线，确认反馈正常。

## 构图

- 每关一个视觉主体（一座塔、一座桥、一组台阶），两到三座岛屿，留出足够的空白。
- 场景在屏幕坐标上的范围不超过 14 × 14，保证手机竖屏也能看清。
- 起点和终点在开局时都要能看见。
- 路面顶板统一用浅色，结构积木按[美术方向](art-direction.md#配色)的用途选色，机关积木用青绿，把手用金色。
- 装饰物（树、花）每关 3～6 个，只放在岛屿地面上，不放在路面上，也不放在任何路面的屏幕下方相邻处。
- 塔身的可见侧面可以加窗洞，每座塔 2～5 个。

## 解法格式

```ts
type SolutionStep =
  | { type: 'walk'; to: Vec3 }           // 走到「此刻」位于该坐标的路面
  | { type: 'operate'; mechanism: string } // 点击该机关的把手一次
```

- `walk.to` 是执行这一步时目标路面所在的世界坐标；机关上的路面按它当时的位置填写。
- 压板不需要单独写步骤：走到压板上停下就会触发。
- 解法最后一步必须走到终点。

## 校验

`src/game/levels/levels.test.ts` 对每个关卡执行以下检查，全部通过才算合格：

1. **基本结构**：关卡编号唯一；起点、终点都是路面；终点不在机关上；机关编号唯一；压板绑定的机关存在。
2. **无重叠**：在每个机关的每个档位或停靠位组合下，没有两块积木占用同一格。机关组合数超过 64 时，只检查初始状态和解法每一步之后的状态。
3. **解法可行**：用模拟器从初始状态逐步执行解法，每一步都必须成功（行走可达、机关未被阻止），最后一步结束时状态为通关。
4. **可见性**：执行解法的过程中，每次行走经过的所有路面（含起点和终点），在行走开始时顶面都必须可见。检查方法：在顶面取 5 个采样点（中心，以及沿 `x`、`z` 方向各偏移 ±0.35），从每个点沿 `(1, 1, 1)` 方向发射射线，不能碰到其他任何积木。
5. **遮挡规则**：解法中每次跨越错觉连接（相连但三维不相邻的两块路面），都满足上文的遮挡规则。
6. **把手可见**：每个机关把手所在的侧面中心点，沿 `(1, 1, 1)` 方向不被其他积木挡住。
7. **构图范围**：所有积木的屏幕坐标范围不超过 14 × 14。

## 常见错误

- 错觉连接往屏幕下方走时高度降低了，违反遮挡规则。
- 高处路面下面没有柱子，看起来像悬空，破坏积木感。
- 机关旋转后和旁边的积木重叠。
- 把手装在背面（`-x` 或 `-z` 面），玩家看不见。
- 树放在路面前方，挡住了路或小人。
- 一关同时引入两种新机关，玩家不知道该注意什么。
