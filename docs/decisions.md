## 玩法

| 编号 | 决策 | 理由 |
| --- | --- | --- |
| D10 | 连通规则：屏幕坐标 `(x - y, z - y)` 上下左右相邻即相连 | 核心玩法，见设计稿 |
| D11 | 相机固定为等距正交视角，玩家不能旋转、缩放 | 保证每关的错觉成立 |
| D12 | 机关：**转盘**、**平移台**、**压板**、**开关门**。转盘和平移台可以**联动**其他机关，把手可以省略（只能被联动或压板驱动）（改版） | 联动制造取舍，无把手机关制造间接操作 |
| D12a | **可推积木**：小人与积木屏幕相邻时，点击积木把它沿「小人指向积木」的屏幕方向推一格，可以推过错觉连接（改版新增） | 推箱子类谜题与错觉结合，是第 4 章的核心 |
| D12b | 压板分两种：**触发压板**（停上去触发一次）和**按住压板**（被小人、积木或巡逻者静止压着时生效，离开即恢复）。按住压板**只控制按住门**；门里有东西时不会关闭；寻路时小人自己压着的按住压板视为已松开（改版新增） | 「先用积木压住，人再过去」，且不能自己压着自己过门 |
| D12c | **单向格**与**限次把手**作为点缀，不单独开教学关（改版新增） | 制造不可逆选择与资源规划 |
| D12d | **遮挡断路**：路面顶面中心被前方积木挡住时，不能进入也不能点击。全局规则，**阶段一就实现**，所有关卡按最终规则设计。T6.12o 目标第五关提前体验一次显露，第 5 章承担进阶应用；目标第五关尚待 T6.12t 实现 | 「看不见就不存在」；规则不变，教学顺序随试玩校准 |
| D12e | **巡逻者**：沿固定路线移动的小生物，玩家每完成一个动作它走一格，占着的格子小人不能进入，也能压住按住压板；同样遵守单向格（改版新增） | 增加时机与站位的考虑 |
| D12f | **规模上限**：每关最多 2 个积木箱、1 个巡逻者；可达状态数主线不超过 30000、挑战关不超过 100000；提示在后台线程预先算好（改版新增） | 保证求解器和提示的速度 |
| D13 | 机关一律**点击把手**操作，不做拖拽 | 电脑和手机操作一致，解法可以写成确定的步骤 |
| D14 | **允许乘坐**：小人站在转盘或平移台的积木上时，机关照常运动，小人随之一起移动（改版，取代旧规则「站在机关上不能操作」） | 位置成为资源，是解谜深度的最大来源 |
| D15 | **主线 15 关，分 5 章**，一遍 50～70 分钟；另有**挑战章 5 关**，集齐某章全部选做光点后解锁该章对应的挑战关，不影响结局（改版） | 体量与难度曲线；选做光点有明确回报 |
| D15a | **分三阶段交付**：一、前四章 12 关及其机制（含遮挡断路规则），第 1～2 章做完先让用户试玩校准；二、巡逻者、第五章与完整结局；三、挑战章。每个阶段结束都是完整可玩、可以发布的版本（改版新增） | 避免做到一半全盘停滞，尽早发现方向问题 |
| D16 | 进度存在浏览器本地存储，键名 `seemingly:save:v2`；关卡已全部重做，**不迁移**旧版进度，只保留静音设置（改版） | 旧关卡编号已失效 |
| D17 | 叙事：每关终点有一盏灯笼，集齐必需光点后抵达才会点亮；终章点亮主线 15 盏灯笼，照亮一座塔。没有对话文字（改版） | 轻叙事，光点给路线规划一个目标 |
| D18 | 每关必须附带标准解法，并满足[难度目标](level-design.md#难度指标)；指标由求解器计算，在测试中强制检查（改版） | 防止再出现「点两下就过」的关卡 |
| D19 | **光点**：放在路面上，路过即收集。分「必需」和「选做」，必需光点集齐才能点亮灯笼；第 2 章起每关有 1 个选做光点，集齐一章的选做光点解锁该章挑战关；第 1 章的挑战关在第 1 章全部通关后解锁（改版新增） | 路线规划与重玩目标 |
| D19a | **撤销**：可无限撤销玩家动作（行走、推动、操作），立即恢复到动作前的状态；重新开始清空记录（改版新增） | 允许大胆尝试，减少挫败 |
| D19b | **步数**：每次行走、推动积木或机关操作计 1 步，撤销会减去对应步数（改版新增） | 评价标准 |
| D19c | **三项评价**：抵达；集齐全部光点；步数不超过该关最少步数（由求解器算出）（改版新增） | 给愿意钻研的玩家目标 |
| D19d | **提示**：游戏页有提示按钮，高亮下一步最优动作；本局用过提示则不能获得步数评价（改版新增） | 难度提高后给普通玩家兜底 |

## 声音

| 编号 | 决策 | 理由 |
| --- | --- | --- |
| D20 | 全部用 Web Audio 实时合成，不引入音频文件 | 零体积、无版权问题 |
| D21 | 音效带音高：脚步、机关、光点、灯笼都从当前和弦的音阶取音；走不通用柔和的低音（改版） | 操作本身成为音乐；T6.12b 第六关、T6.12e～i 第一至第五关脚步以轻木质触感为主，机关、光点和灯笼保留和声回应 |
| D22 | 环境音乐为**生成式**：和弦循环铺底、低音、随机八音盒音，加混响；每章换调式和速度；首次点击后开始播放（改版）。T6.12b 第六关、T6.12h～i 第四、五关使用 96 秒原创乐句与材质交互声，仍使用 Web Audio 合成；T6.12e～g 第一至第三关使用 C 大调章节乐句，共用已认可音色与混音；其余关卡保留原配置 | 首版只有三个正弦长音，单调；音乐是否适合由实际游玩试听判断 |
| D23 | 右上角有静音开关，状态存入本地存储 | 尊重玩家选择 |

## 技术

| 编号 | 决策 | 理由 |
| --- | --- | --- |
| D30 | Vite + React 19 + TypeScript + Three.js + React Three Fiber + drei | 小样已验证 |
| D31 | 游戏规则写成纯 TypeScript 的**规则层**（瞬时状态转移），模拟器在其上做动画，求解器复用同一规则层（改版） | 游戏、测试、提示三者规则一致 |
| D32 | 页面级状态（当前页面、当前关卡、进度、静音、画质）用 zustand 管理 | 简单、类型友好 |
| D33 | 关卡用 TypeScript 文件编写，每关一个文件；难度目标集中写在 `levels/targets.ts` | 目标与关卡分离，防止为通过测试而改目标 |
| D34 | 测试用 Vitest；格式化用 Prettier；不引入 ESLint | 工具越少越不容易出错 |
| D35 | Node 版本以 `.nvmrc` 为准（当前 24） | 本地与 CI 一致 |
| D36 | 只在 `main` 分支开发；推送到 `main` 自动检查并发布 | 个人项目，流程从简 |
| D37 | 画质分两档：手机或粗指针设备默认低画质，其余默认高画质；可用网址参数 `?quality=low` 或 `?quality=high` 强制指定 | 低配设备也能流畅 |
| D38 | 系统开启「减少动态效果」时，关闭场景漂浮、云朵移动和光点粒子 | 无障碍 |
| D39 | **关卡谜题由用户指定的强模型设计**（输出关卡设计稿），其他 AI 只按设计稿实现，不得自行设计或删改谜题（改版新增） | 谜题设计是可玩性的关键 |

## 明确不做

- 关卡编辑器、用户自制关卡分享
- 自由视角、自由建造
- 拖拽操作机关
- 多语言
- 过场动画、对话、文字剧情
- 计时、排行榜
