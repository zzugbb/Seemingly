## 怎么用参考实现

- 先确认任务编号与当前实现状态，再将对应稿「参考实现」代码复制到同名源码文件。坐标、kind、机关、光点、装饰、解法及 metadata 按稿执行，不另外补路或改颜色。
- 在同一关的实现提交里同步该关revision、行为测试和状态；targets按已定难度目标执行，不为迎合校验而修改；不能先整表换成未来目标，再要求未改的旧关通过。
- 第一关不换数据、不提 revision。第六关已在 t1 按回环稿替换并升至 revision 4。旧第二至第四关只留在 Git 历史，不能擅自改成挑战关或隐藏入口。
- 新四、新五关的参考实现已经包含来源转换。不要从届时可能已替换的旧第五关文件取数据，不要直接把 sample-01 对象放进 mainLevels。
- 某项设计校验或指标不通过时反馈给用户指定设计者；不得靠改目标、删测试或修正谜题来迎合实现。四项检查通过后更新路线图并以中文任务提交，不推送。
- 历史 T6.12e～n 的逐轮记录解释当时提交；前六关历史实现依据为T6.12o／o1；当前第八至十二关开发以T6.14a第三稿和b～g任务为准。T6.11 的删除首版九关迁移已完成，不要再执行一次。

## 怎么读屏幕草图

每份稿先写明草图符号，通常 `(a,b)=(x-y,z-y)`，数字为高度、`@` 起点、`G` 灯笼、`o` 必需光点、`O` 选做光点。世界坐标在积木清单和参考实现内。

屏幕上下左右相邻才相连，斜对角不算；三维高低差不另作门槛。被前景积木遮住的路面不能进入，遮挡规则与 [规范](../level-design.md#遮挡规则) 一致。不要把投影草图当成世界坐标直接搭建。
