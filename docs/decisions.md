# 项目决策

本文只保留当前有效约定。产品已完成开发并发布；十五个主线关卡、五个挑战、完整结局和当前声音已获用户试玩确认。逐轮讨论、被替代的方案及实施过程见 Git 历史，不作为待办。

## 产品

| 编号 | 决策 |
| --- | --- |
| D01 | 英文名 Seemingly，中文名积木错位 |
| D02 | MIT 许可证，署名 zzugbb；画面由代码生成 |
| D03 | 纯静态站点，通过 GitHub Actions 发布到 [GitHub Pages](https://zzugbb.github.io/Seemingly/) |
| D04 | 支持电脑和手机浏览器，要求 WebGL2；不支持时显示说明 |
| D05 | 不做账号、排行榜、统计、广告或后端 |
| D06 | 界面只使用简体中文 |
| D07 | 可玩性优先；谜题有明确的发现与取舍，难度由求解器量化校验 |

## 玩法

| 编号 | 决策 |
| --- | --- |
| D10 | 屏幕坐标 `(x - y, z - y)` 上下左右相邻即连通，不附加三维距离或高度差限制 |
| D11 | 固定等距正交相机，方向 `(1, 1, 1)`；玩家不能旋转、缩放 |
| D12 | 转盘、平移台、触发／按住压板、切换／按住门；机关可单层联动，无把手机关只能间接驱动 |
| D12a | 小人与箱屏幕相邻时可推一格，允许跨错觉连接和运箱乘坐 |
| D12b | 按住压板只控制按住门；小人、箱、巡逻者静止压着才生效。寻路按小人已离板求值，门内有占位时不关闭 |
| D12c | 单向格只限制进入方向；限次把手消耗操作额度 |
| D12d | 路面顶面中心被前景积木遮住时不能进入或点击，已站在其上仍可离开 |
| D12e | 每个完整合法动作后巡逻者前进一步，受阻等待；能压住按住压板，遵守单向与遮挡，不靠现实时间推进 |
| D12f | 每关最多两个箱、一个巡逻者；主线最多 30000、挑战最多 100000 可达状态；提示在 Worker 中建立策略 |
| D13 | 机关通过点击把手操作，不做拖拽 |
| D14 | 小人站在机关积木上时照常驱动，随机关一起移动；机关运动期间不接受行走输入 |
| D15 | 五章十五个主线关卡，加五个独立挑战；挑战不影响主线结局 |
| D15a | 正式体量已完成，不保留开发过渡入口或占位关卡 |
| D16 | 本地存储键 `seemingly:save:v2`，逐关 revision 失效旧评价；首版进度不迁移，只保留静音 |
| D17 | 必需光点集齐后抵达终点灯笼；第十五关点亮十五灯与一座塔，无对话叙事 |
| D18 | 每关有完整正式设计稿和自动验证的最优标准解法；指标不通过不得擅改谜题或 targets |
| D19 | 必需／选做光点路过即收集。第一章通关解锁挑战一，后四章全收集解锁对应挑战 |
| D19a | 无限撤销完整动作；行走中可撤销，机关运动中须等到位；重开清空本局动作 |
| D19b | 一次行走、推动或机关操作各计一步；行走中改道不多计步，撤销减步 |
| D19c | 抵达、全收集、最少步数三项历史评价独立累计，共六十项，不被较差重玩覆盖 |
| D19d | 主动提示高亮最优下一步；本局实际使用提示后不授予本局步数评价，提示故障不计使用 |

## 声音与表现

| 编号 | 决策 |
| --- | --- |
| D20 | 全部声音由 Web Audio 合成，无外部音频文件 |
| D21 | 操作反馈使用当前和弦；收光、集齐必需、选做、点灯、新评价各有反馈 |
| D22 | 五章使用原创主题乐句和生成的铺底／律动；挑战沿用母章谱面，以 90% 速度统一缩放时钟。当前谱面和混音已获用户确认 |
| D23 | 首次交互解锁音频；静音存本地，停止音源与调度，恢复不补播旧效果 |
| D24 | 暖色低饱和积木、浅色路面、青绿机关、金色交互；规范见[视觉规范](design.md#视觉规范) |
| D25 | 主线与挑战分开统计；下一编号挑战已解锁才提供“下一关”，不跳过锁定关 |
| D26 | 主线全通后提供本地旅程成绩卡，区分主线全通、二十关全通、六十项评价齐全；保存 PNG，按能力调用系统文件分享，不虚构总分／排名／用时 |

## 技术与维护

| 编号 | 决策 |
| --- | --- |
| D30 | Vite、React、TypeScript、Three.js、React Three Fiber、drei，版本以 package-lock.json 为准 |
| D31 | 规则只写在 `src/game/core/rules.ts`；模拟器、求解器、提示共用。core 不依赖渲染库 |
| D32 | 页面状态用 zustand；页面临时预览和成绩卡状态不写存档 |
| D33 | 关卡数据在 `src/game/levels/`；正式设计在 `docs/levels/`，难度目标集中在 targets.ts |
| D34 | Vitest 测试、Prettier 格式化；不增加 ESLint 或其他依赖 |
| D35 | Node 24，以 `.nvmrc` 为准 |
| D36 | 在 main 开发，推送后自动检查与发布；推送／发布须用户明确指示 |
| D37 | 粗指针设备默认低画质，其余高画质；可用 `?quality=low` 或 `?quality=high` 指定 |
| D38 | 减少动态效果时关闭漂浮、云移动与光粒，保留必要动作位移 |
| D39 | 谜题由用户指定的设计者制作；实现者按正式稿执行，不擅改谜题、targets 或删减验收 |
| D40 | 只保留正式运行与维护必需内容：不保留独立开发样段、开发指标打印入口和原型附件；正式设计、独立基准、有效测试及验证边界保留 |
| D41 | 开源协作入口为贡献指南、求助说明、行为准则、安全政策及 Issue／PR 模板；不重复运行和设计文档，不虚构私密渠道、响应时限或旧版本支持承诺 |

允许的依赖：运行时 `react`、`react-dom`、`three`、`@react-three/fiber`、`@react-three/drei`、`zustand`；开发时 `vite`、`@vitejs/plugin-react`、`typescript`、`@types/react`、`@types/react-dom`、`@types/three`、`vitest`、`prettier`。新增依赖、外部素材、核心玩法或风格变更须先获得用户同意。

不做自由镜头、自由建造、拖拽机关、关卡编辑器、用户自制关卡分享、多语言、计时、排行榜、对话或第三方脚本。个人主页任务 T5.4 继续暂缓。手机真机分享／保存、Safari 兼容及目标设备长期帧率仍待补验，见[验收记录](performance.md)。
